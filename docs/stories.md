# Истории, оценки и комментарии

Войдите в Angular-приложение и откройте **Лента историй** (`/feed`). Можно читать чужие истории, публиковать свои и переключиться на **Мои истории**. Полный текст и обсуждение открываются по заголовку или ссылке «Читать историю». Редактирование/удаление доступны только автору; сервер проверяет права независимо от UI.

Это текстовые публикации без срока исчезновения: заголовок до 160 символов, текст до 20 000, комментарий до 2 000. Пустой/пробельный текст, NUL и неизвестные поля отклоняются. HTML отображается обычным текстом, без исполнения. Автор берётся из проверенного `account_id`, совпадающего с JWT `sub`. Email и приватные поля профиля не публикуются. Отображается `displayName` профиля или «Читатель», если профиль ещё не заполнен. Удаление профиля не удаляет историю или аккаунт; имя в ленте становится «Читатель».

## HTTP-контракт

Все маршруты под `/api/v1/stories` требуют пользовательский JWT. Чтение требует `api.read`, изменения — `api.write`. Machine token не предоставляет доступ к ленте.

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/v1/stories?mine=false&limit=10&cursor=…` | Лента; `mine=true` — свои |
| POST | `/api/v1/stories` | Создать: `{ "title": "…", "body": "…" }` |
| GET | `/api/v1/stories/{id}` | История, счётчики, `myReaction`, `ETag` |
| PUT | `/api/v1/stories/{id}` | Изменить свою; тот же JSON и `If-Match` |
| DELETE | `/api/v1/stories/{id}` | Удалить свою с `If-Match` |
| PUT | `/api/v1/stories/{id}/reaction` | `{ "value": 1 }` — лайк, `-1` — дизлайк, `0` — снять |
| GET | `/api/v1/stories/{id}/comments?limit=10&cursor=…` | Корневые комментарии, sort=newest/oldest/popular |
| POST | `/api/v1/stories/{id}/comments` | `{ "body": "…", "parentId": "…" }`; parentId необязателен |
| GET | `/api/v1/stories/{id}/comments/{commentId}` | Комментарий и текущий ETag |
| PUT | `/api/v1/stories/{id}/comments/{commentId}` | Изменить свой: `{ "body": "…" }` и `If-Match` |
| DELETE | `/api/v1/stories/{id}/comments/{commentId}` | Удалить свой комментарий |
| GET | `/api/v1/stories/{id}/author/photo` | JPEG аватара автора, с пользовательским Bearer token |

Оценки можно ставить и своим историям. Смена лайка на дизлайк заменяет голос, а не добавляет второй. Повторная отправка того же значения идемпотентна. В UI повторное нажатие активной кнопки отправляет `0`. Комментарии к чужим историям разрешены; удалять чужие комментарии, в том числе автору истории, нельзя. Отдельной роли модератора пока нет.

Редактирование текста и удаление требуют `If-Match: "0"` (актуальный `ETag` из GET). Без него возвращается 428, при устаревшей версии — 412. Версия истории относится к её тексту: оценки и комментарии её не меняют. У каждого комментария отдельная версия и `updatedAt`; PUT комментария требует его собственного `If-Match`, иначе 428/412. GET одного комментария возвращает актуальный текст и ETag. Автор истории не получает право редактировать чужие комментарии. При конфликте редактор сохраняет черновик и позволяет получить свежую версию перед осознанным повторным сохранением.

Лента/комментарии возвращают `{ "items": […], "nextCursor": "…" }`; `null` завершает список. Курсор содержит пару `(created_at, id)`. Это keyset pagination без OFFSET; новые публикации и удаление последней записи страницы не сдвигают продолжение. Время создания неизменно при редактировании. Размер страницы — 1–20. Ответы `no-store`, поскольку `myReaction` зависит от пользователя. Модель story включает полный текст, поэтому страницы ограничены; для большой нагрузки можно выделить краткую feed-проекцию после замеров.

## Хранение и конкурентность

Миграция Flyway `V2__stories.sql` добавляет `stories`, `story_reactions`, `story_comments` в существующую БД domain-service, не изменяя V1 и данные профилей. Для ленты и комментариев добавлены составные индексы. FK с `ON DELETE CASCADE` удаляют оценки/комментарии вместе с историей. Они не связаны FK с профилем: публикация не требует заполнить профиль.

Уникальный первичный ключ `(story_id, account_id)`, CHECK на `-1/1` и `INSERT … ON CONFLICT DO UPDATE` обеспечивают один голос на уровне PostgreSQL при конкурентных запросах. Оценки и новые комментарии берут `FOR KEY SHARE` на историю в транзакции: разные пользователи не блокируют друг друга, удаление истории корректно сериализуется. Изменение/удаление текста использует атомарное условие `id + author_id + version`. Счётчики читаются из индексированных таблиц и не дублируются в отдельных изменяемых колонках. Никакого распределённого lock или Kafka для этой атомарности не требуется.

API-сервис передаёт исходный JWT и разрешённые заголовки через общий `DomainBackend`/`DomainHttpClient`; domain повторно проверяет подпись, audience, scopes и авторство. Nginx ограничивает JSON историй до 128 KiB и применяет существующее ограничение частоты запросов. Метрики новых HTTP-маршрутов автоматически попадают в существующий Grafana-дашборд.

## Запуск и проверки

```sh
docker compose up -d --build --wait --wait-timeout 180
python3 scripts/test-stories.py
```

Миграция запускается автоматически. Не удаляйте volumes для обновления. Фронт находится в отдельном `plot-twist-web`; его также нужно обновить и перезапустить. Сквозной тест фронта: `CHROMIUM_PATH=/usr/bin/chromium npx playwright test e2e/stories.spec.ts --project=backend` при запущенных локальных Compose и Mailpit (на других ОС путь Chromium не обязателен).

Проверки создают временные аккаунты в локальном Mailpit-окружении, затем удаляют созданные тестовые истории. Проверяются права двух пользователей, конфликт версий, одновременные голоса, курсоры, комментарии и каскадное удаление. Unit/ArchUnit тесты входят в Maven-сборку. Полный контракт — [openapi.json](openapi.json).

Для публичного запуска понадобятся продуктовые правила модерации, жалоб и антиспама. Если появятся уведомления о комментариях/оценках, их можно отправлять через outbox + Kafka/RabbitMQ после коммита, не помещая брокер в синхронную запись оценки.

## Понравившиеся и аватары

`GET /api/v1/stories?liked=true` возвращает только текущие лайки вошедшего пользователя. Параметра чужого account ID нет. Сортировка остаётся по дате публикации истории, пагинация — по курсору. Дизлайки и снятые оценки исчезают из выборки; `mine=true&liked=true` даёт пересечение. В Angular появилась вкладка «Понравившиеся»; фильтр сохраняется в `?view=liked` и восстанавливается после F5. Индекс `(account_id, story_id) WHERE value=1` добавлен миграцией V3.

У Story есть `authorPhotoSha256`: null, если активного фото нет. API `/stories/{id}/author/photo` показывает вошедшим читателям только обработанный JPEG автора существующей истории. Личные поля профиля и приватный `/profile/photo` не открываются другим пользователям. S3 остаётся закрытым; object key не попадает в JSON. Фото отображается в ленте и на странице истории. При удалении фото/профиля API возвращает 404, в интерфейсе остаются инициалы.

Angular скачивает аватар через HttpClient с Authorization, затем использует Blob URL. Токена в URL картинки нет. Повторные авторы с одинаковым hash используют общий Promise в ограниченном кеше страницы (40 записей); кеш не сохраняется на диск, Blob URL освобождаются при смене/уничтожении компонента. При ошибке загрузки показываются инициалы.

V3 добавляет `version` и `updated_at` комментария, заполняя время существующих записей из `created_at`. Предыдущие миграции и данные сохраняются. При редактировании SQL проверяет `story_id + id + author_id + version` атомарно. UI сохраняет черновик при 412 и предлагает обновить версию перед повторным сохранением.


С версии 1.4 создание/правка асинхронны и возвращают **202 Accepted**. Новые рабочие копии проходят модерацию; подробности и новые поля ответа описаны в [moderation.md](moderation.md).

## Картинки, GIF и видео

В `body` поддерживаются типизированные вставки `![Подпись](attachment:UUID)`, до восьми файлов. Загрузка, приватные ссылки, версии вложений и техническая проверка описаны в [story-media.md](story-media.md). Это не произвольный HTML/Markdown: сторонние URL не загружаются как медиа. В ответе истории появился массив `attachments`.

## Страница автора

Ник и аватар истории/комментария ведут на `/users/{accountId}`: ник, описание, фото и одобренные истории автора. [Контракт и приватность публичных профилей](public-profiles.md).

## Лента подписок

Вкладка «Подписки» (`/feed?view=following`) использует `GET /api/v1/stories/following` и показывает одобренные истории авторов, на которых подписан JWT-пользователь. [Подписка/отписка и семантика ленты](follows.md).

Лайки комментариев, сортировки, ответы на ответы и сохранение веток при удалении родителя добавлены миграцией V13. [Подробный контракт и правила](comments.md).
