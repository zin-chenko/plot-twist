# Профили пользователей

В Angular нажмите на ник или аватар автора истории/комментария. Страница `/users/{accountId}` показывает ник, описание, фото и опубликованные истории от новых к ранним; следующие страницы загружаются кнопкой. Есть переход к полному тексту и комментариям. Меню «Мой профиль» открывает `/profile` с тем же оформлением и опубликованными историями, что и у других авторов. Кнопка «Редактировать профиль» ведёт в отдельную форму `/profile/edit`, а «К профилю» возвращает к просмотру. Для нового аккаунта без заполненного профиля показано приглашение добавить ник, описание и фото. Управление черновиками и проверяемыми версиями остаётся в «Моих историях».

Ник — существующее поле **«Как вас называть» / displayName**, описание — **«О себе» / bio**. Это отображаемое имя, не отдельный уникальный `@handle` и не логин. Адрес использует стабильный UUID, поэтому смена ника не ломает ссылки. Ник, описание и фото теперь доступны другим вошедшим пользователям. Имя, фамилия, дата рождения, email, версия приватного профиля и S3-ключи не входят в публичный ответ. В форме настройки объяснено, какие поля видны читателям.

## API и доступ

Все три GET требуют проверенный пользовательский JWT со scope `api.read`. «Публичный» здесь означает доступный другим пользователям приложения; анонимного доступа и доступа через machine grant нет.

- `GET /api/v1/profiles/{account}` — `{accountId, displayName, bio, photoSha256, followersCount, followingCount, following}`. Пустые описание/фото — `null`. Если заполненного профиля нет, но есть опубликованные истории или связи подписки, возвращается «Читатель» без описания/фото. Неизвестный ID и автор только неопубликованных историй без заполненного профиля — `404`.
- `GET /api/v1/profiles/{account}/photo` — обработанный JPEG с проверкой SHA-256, `ETag`, `Cache-Control: no-store`; без фотографии — `404`. S3 остаётся приватным, браузер получает blob через авторизованный API.
- `GET /api/v1/profiles/{account}/stories?limit=10&cursor=…` — `{items, nextCursor}`, лимит 1–20. Курсор использует `(created_at, id)`, без offset. Публикации другого автора, черновики и отклонённые новые истории не попадают в ответ.

Публичная страница показывает **одобренный снимок даже самому автору**. Пока правка на модерации/отклонена, читатели видят прежние текст, версию и вложения. `myReaction` при этом принадлежит фактическому читателю. Управление рабочими версиями остаётся в «Моих историях». Существующий `/api/v1/profile` сохраняет приватный ответ и запись только владельцем; PUT/DELETE чужого публичного профиля запрещены.

HTML в нике/описании/тексте не исполняется: Angular выводит обычный текст. F5 и восстановление сессии возвращают на тот же `/users/{id}`, `/profile` или `/profile/edit`, проверяя собственный origin и разрешённый формат маршрута.

## Обновление и проверка

Новых миграций БД и секретов для этой функции нет. Нужна существующая схема V8 от предыдущего обновления с медиа. Обновите backend в ветке `feature/spring-boot-docker-compose` и frontend в `main`, пересоберите domain/API и frontend:

```sh
# backend, зависимости уже работают
git pull
docker compose up -d --build --no-deps --wait domain-service api-service
# frontend, из его каталога
git pull
docker compose up -d --build --wait
# либо перезапустите npm start
```

Проверка backend с отдельной PostgreSQL, без полного приложения:

```sh
docker compose -p plot-twist-profile-test -f compose.profile-test.yaml run --rm --build profile-tests
docker compose -p plot-twist-profile-test -f compose.profile-test.yaml down -v
```

Тесты покрывают явную публичную проекцию, фотографию, права, пагинацию, pending-правки, отсутствие черновиков и fallback автора без заполненного профиля. S3 и publisher в этих тестах заменены адаптерами-заглушками; чтение и транзакции используют настоящую PostgreSQL. API-gateway отдельно проверяется на передачу JWT, курсора/лимита и запрет machine/анонимных запросов. Изолированный CI job не использует пользовательские volumes.

Angular UI-тест использует HTTP/OAuth fixtures и проверяет реальные маршруты и компоненты, переход по автору, аватар, безопасный вывод описания, пагинацию, F5, 404 и мобильную ширину. Для запуска на свободном порту можно задать `PLAYWRIGHT_PORT=4300 npm test`; backend для UI-набора не нужен. Для браузерных тестов с настоящим backend порт callback должен быть зарегистрирован в auth-service.
